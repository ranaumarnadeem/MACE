What's new

Three commits' worth of real capability, each proven against actual hardware or a live LLM backend — not a mock, not a unit test standing in for a real run.

The mace CLI new

A real interactive shell, modeled on Yosys/OpenROAD's own command style — read_verilog, top_module, read_spec, set_core, then run. State accumulates across commands the way a real EDA tool session does. Rich-rendered output: styled pass/fail, bordered panels for verification logs, a real command-reference table.

try it mace shell --piton-root <path> --api <.env>
mace/cli/shell.py mace/cli/session.py
Vertex / Gemini backend new

A second real LLM backend end to end, not just OpenCode — Google Vertex AI's Gemini models, authenticated via Application Default Credentials (no API key file at all, since ADC was already set up on this machine from earlier cluster work). Confirmed gemini-2.5-flash is what actually works on our project/region; gemini-2.0-flash-001 404s.

real run run_id f0ed1fe44745 · status=passed · 1x1 Ariane + barrier_atomic.c
mace/llm.py chia.models.vertex.VertexGeminiLLM
Verilator code coverage new

Real line-coverage instrumentation, wired the whole way from a testbench patch to a live run -coverage command. Needed a genuine fix to OpenPiton's own hand-written testbench (it never called Verilator's coverage-write API), plus routing around a broken verilator_coverage install this project's own build environment resolves to first — both real, both documented in the script below.
